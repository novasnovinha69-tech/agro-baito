# 🌾 Agro Mundo Animal — E-commerce (MVP Completo)

E-commerce completo no estilo Anota.ai, adaptado para a **Agro Mundo Animal (Tabuleiro/Florianópolis-SC)**. Stack moderna, deploy na Vercel, integrações reais com Mercado Pago (Pix) e WhatsApp Business API.

---

## 🏗️ Arquitetura Técnica

| Camada | Tecnologia |
|---|---|
| **Frontend** | Next.js 14 (App Router) + TypeScript + Tailwind CSS + shadcn/ui |
| **Backend** | Next.js Route Handlers (`app/api/*`) + Server Actions |
| **Banco de Dados** | Supabase (PostgreSQL + Auth + Storage + Row Level Security) |
| **Auth** | Supabase Auth (e-mail/senha p/ admin; Magic Link opcional p/ clientes) |
| **Pagamentos** | Mercado Pago SDK Node (`mercadopago/sdk`) — Pix dinâmico + webhook |
| **WhatsApp** | Meta WhatsApp Business Cloud API (`graph.facebook.com/v18.0`) — templates + webhook |
| **Imagens** | Supabase Storage (bucket `produtos`) + upload via admin |
| **Validação** | Zod (schemas compartilhados cliente/servidor) |
| **Estado** | Zustand (carrinho) + persistência localStorage + sincronização DB |
| **Deploy** | Vercel (variáveis de ambiente no dashboard) |

## 🗄️ Schema do Banco (PostgreSQL/Supabase)

Tabelas principais (com **Row Level Security** em tudo):

- **`categorias`** (id, nome, slug, icone, ordem)
- **`produtos`** (id, categoria_id, nome, slug, descricao, preco_cents, **preco_por_kg** bool, **peso_kg**, estoque, **estoque_minimo**, **qtd_minima**, **multiplo**, foto_url, ativo, created_at)
- **`unidades`** (id, nome, slug, endereco, whatsapp, ativa) — Tabuleiro + Centro
- **`zonas_entrega`** (id, unidade_id, nome, tipo [`retirada`|`bairro`|`cidade`], valor, **frete_percentual**, prazo_horas, ativa)
- **`pedidos`** (id, codigo `AMA-0001`, cliente_nome, cliente_telefone, cliente_email, cpf_cnpj, subtotal_cents, frete_cents, total_cents, zona_id, endereco jsonb, tipo_entrega, status, pagamento_id, pix_qr, observacoes, created_at, updated_at)
- **`pedido_itens`** (id, pedido_id, produto_id, nome_snapshot, preco_cents_snapshot, quantidade, peso_kg)
- **`status_historico`** (id, pedido_id, status, observacao, created_at) — timeline
- **`admins`** (id, user_id → auth.users, nome, email, role)
- **`config_loja`** (chave, valor) — settings gerais

**Funções SQL:**
- `baixar_estoque(pedido_id)` — trigger pós-pagamento confirmado
- `recalcular_estoque()` — view de alertas
- `gerar_codigo_pedido()` — sequence formatada

**Políticas RLS:**
- Produtos/categorias/zonas: leitura pública, escrita só admin
- Pedidos: leitura pelo telefone (hash) do cliente OU admin
- Admin tables: só role `admin`

## 🔄 Fluxos Principais

### 1. Compra (visitante)
1. Cliente navega catálogo → adiciona ao carrinho (Zustand + localStorage)
2. Validação de estoque em tempo real ao adicionar e ao checkout
3. Checkout: dados + endereço → **escolhe zona de entrega** → **frete calculado na hora** (% sobre subtotal)
4. Geração do Pix dinâmico (Mercado Pago) → QR Code + Copia e Cola
5. Webhook MP confirma pagamento → baixa estoque + cria pedido + status `confirmado`
6. WhatsApp envia confirmação ao cliente e à loja (template aprovado)
7. Cliente acompanha status em `/pedido/[id]`

### 2. Frete por zona
- Admin configura zonas: `Bairro Centro (Tabuleiro) - 10%`, `Florianópolis - 15%`, `São José - 18%`, etc.
- Endpoint `/api/frete/calcular` recebe CEP/bairro + subtotal → retorna valor e prazo
- Validação: bairro/cidade fora das zonas = "não atendemos para entrega (retirada disponível)"

### 3. Admin
- Login via Supabase Auth → middleware valida role `admin`
- CRUD de produtos com upload de foto (Supabase Storage)
- Pedidos com timeline de status → mudança de status dispara WhatsApp ao cliente
- Dashboard: vendas do dia/mês, ticket médio, produtos mais vendidos, alertas de estoque

## ⚠️ Observações Importantes

1. **WhatsApp Business Cloud API oficial** exige: conta Meta Business, número verificado, aprovação de templates (pode levar horas/dias). Vou estruturar tudo pronto + fallback com link `wa.me` caso os templates ainda não estejam aprovados.
2. **Mercado Pago** requer conta de produtor (vendedor). Em sandbox não baixa dinheiro real — ótimo para testar.
3. **Supabase** tem free tier generoso suficiente para MVP.
4. Como o checkout é **visitante**, a área "meus pedidos" será acessada por link mágico enviado via WhatsApp/e-mail (ou o cliente cria conta opcional depois).
5. **Fotos de produtos**: no seed vou usar placeholders; o admin sobe as reais via painel.
