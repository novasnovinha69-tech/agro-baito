# Plano: Plataforma de Anúncios de Acompanhantes (estilo Fatal Model) — MVP

## Decisões alinhadas com você
- **Local**: nova subpasta isolada `./plataforma-modelos` (não toca no projeto Agro existente).
- **Stack**: Next.js 14 (App Router) + TypeScript + Tailwind + shadcn/ui (radix) + Prisma + PostgreSQL.
- **Auth**: NextAuth (Credentials) com roles `MODELO`, `CLIENTE`, `ADMIN` + 2FA TOTP (otplib + qrcode).
- **Upload**: local em `/public/uploads` com compressão via Sharp, com abstração (`storage.ts`) para migrar a Cloudinary depois.
- **Escopo**: núcleo funcional rodando localmente com **SQLite** (Prisma troca pra Postgres só mudando o `provider`/`DATABASE_URL` — mantenho o schema 100% Postgres-compatible). Seed com dados de exemplo.

## Por que SQLite localmente
Para o projeto rodar de imediato sem configurar Postgres. O `schema.prisma` usa tipos compatíveis. Quando for pra produção, basta trocar `provider = "sqlite"` → `"postgresql"` e ajustar `DATABASE_URL`. Deixo isso documentado e comentado.

## Schema do banco (entidades principais)
- **User** `{ id, email, senhaHash, role, twoFactorSecret, twoFactorAtivado, criadoEm }`
- **Modelo** `{ userId, slug, nomeArtistico, bio, idade, cidade, estado, bairro, temLocal(bool), fazDeslocamento(bool), valorBase, servicos[], whatsapp(privado), verificado(bool), statusFoto(string), online(bool), destaque, periodoGratisAte(date), ativo(bool), pausada(bool) }`
- **Midia** `{ id, modeloId, tipo(FOTO/VIDEO/DOC/SELFIE), url, capa(bool), moderacaoStatus(PENDENTE/APROVADA/REJEITADA), criadoEm }`
- **Contato** `{ id, modeloId, clienteId opc, ip, criadoEm }` (contagem de cliques no WhatsApp)
- **ComprovantePix** `{ id, modeloId, clienteNome, valor, registradoPor(adminId), comprovanteUrl, status(PENDENTE/APROVADO/REJEITADO), mesReferencia, criadoEm }` — núcleo do modelo de negócio
- **Cobranca** `{ id, modeloId, mesReferencia, faturamentoBruto, percentual(5), valorDevido, status(ABERTA/PAGA/ATRASADA), pagoEm }` — gerada no fechamento do mês
- **Denuncia** `{ id, alvoModeloId/alvoUserId, motivo, descricao, denuncianteId opc, status }`
- **LogSeguranca** `{ id, userId opc, acao, ip, useragent, criadoEm }`
- Campos sensíveis (CPF, documento do upload) tratados como arquivo sob moderação, não exibidos.

## Núcleo funcional (prioridade 1 — entro aqui primeiro)
1. **Cadastro de modelo** → cria User(role MODELO) + Modelo com `periodoGratisAte = hoje+30d`, `ativo=true`.
2. **Status automático dos 30 dias** → helper `lib/status-30-dias.ts` retorna "Em período grátis (X dias)" ou "Ativa – 5%". Pausa automática se `Cobranca.status=ATRASADA`.
3. **Registro de comprovante PIX** (fluxo pedido):
   - Admin abre `/admin/comprovantes/novo`, escolhe a modelo, digita **valor + nome do cliente**, anexa imagem do comprovante (upload).
   - Cria `ComprovantePix` (status PENDENTE). Admin aprova.
   - Ao aprovar: soma ao `faturamentoBruto` da `Cobranca` do mês correspondente, recalcula `valorDevido = faturamentoBruto * 0.05`.
4. **Fechamento do mês / cobrança** → script/função `lib/comprovante.ts` gera ou atualiza a `Cobranca` mensal e produz o texto do PIX de cobrança (chave + valor) que a modelo paga. Inadimplência → `ativo=false`.
5. **Dashboard da modelo** mostra: dias grátis restantes, contatos recebidos, comprovantes do mês, faturamento, **5% devido**.

## Demais funcionalidades (prioridade 2)
- Home com busca por cidade + listagem com filtros (cidade, com local, idade, preço, serviços, online).
- Página de perfil `[slug]`: galeria (apenas mídia APROVADA), dados, botão "Conversar no WhatsApp" (conta clique, nunca expõe número no HTML), status, denúncia.

- 2FA TOTP no login de modelo/admin.
- Rate limiting simples (in-memory) + logs de segurança.
- Páginas estáticas: Como funciona, Segurança, Termos, Privacidade — todas com o aviso obrigatório: *"Plataforma de publicidade. O pagamento do serviço é feito diretamente entre cliente e profissional. Não somos intermediários."*

## Segurança & LGPD (embutido)
- Senhas com bcrypt; NextAuth Credentials.
- Campos sensíveis nunca retornados em APIs públicas (select explícito no Prisma).
- Número de WhatsApp exposto **só via botão** (URL `wa.me` montada server-side); o perfil público nunca mostra o número como texto.
- Logs, rate-limit, 2FA.
